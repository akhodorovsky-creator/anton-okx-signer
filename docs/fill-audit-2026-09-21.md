# ANTON Signal: fill-level financial audit (2026-09-21)

The current dashboard's `pnlEur` and legacy BTC `/pnl` remain **estimates**. Do not treat them as realized profit, an account statement, annualized strategy returns, or tax records.

`fill-audit.js` is an independent READ-ONLY calculation, invoked by `fill-audit-runner.js` at startup +45s and then hourly. The runner sends only HTTP `GET` methods to an allowlist of OKX trade history and pending-order endpoints via the local signer; it never submits orders. It uses market tickers for open-position valuation. Railway deploy logs emit `ANTON_FILL_AUDIT` only after all three pairs reconcile; otherwise `ANTON_FILL_AUDIT_UNVERIFIED` and the reason. Only derived totals are logged; no API keys, raw fills, or private orders. This process never changes the main execution loop, positions, order parameters or dashboard.

Accounting: retrieve all available order-history, order-history-archive and fills-history pages with OKX `after` pagination; reject pagination anomalies or a 30-page cap. Join `ordId` to orders whose `clOrdId` begins `ANTON`; exclude unrelated account trades; reject an ANTON fill without its order. Deduplicate order overlap, reject duplicate fill IDs and reconcile sum(fillSz) with accFillSz. Reject an outstanding bot order, unsupported third-currency fees, inconsistent balances within the reconstructed strategy inventory and any unavailable endpoint. Sort executions by `fillTime`, account for signed fees in base/EUR, use weighted-average cost for realized P&L and last trade price for unrealized P&L. No future closing commission or slippage is assumed. `taxReady: false` is intentional.

**Not implemented:** persistent, independently verifiable fill-by-fill database; reconciliation against every OKX balance movement, deposit/withdrawal and manually traded asset; point-in-time equity and return including capital inflows; immutable tax statements; restoring a submission of uncertain exchange status after process restart. Railway service has no persistent volume. The 85-day starting-horizon guard prevents calling a truncated three-month API history complete forever. The audit's `completeness` explicitly says `NOT_DURABLE`.

**Release rule:** keep the trading version and backup intact; merge only after syntax + existing safety and new audit tests succeed in CI. Deploy without issuing test trades; check Railway `SUCCESS`, `ANTON_MULTI_READY`, `LEGACY_AUTO_DISABLED`, `ANTON_FILL_AUDIT` or fail reason. A failed audit does not silently replace dashboard profit with zero or affect trading orders. Until persistent storage and full cashflow reconciliation exist, GitHub issue #8 remains open. Do not increase the order size or top up based solely on short-term estimated returns.

Official API reference: https://www.okx.com/docs-v5/en/ (Trade: Order history, Order history archive, Transaction details last 3 months) and https://www.okx.com/docs-v5/trick_en/ (after/before pagination).
